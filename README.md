# charkaLab

Веб-додаток для створення рецептів алкогольних напоїв. На стадії MVP — генератор
рецептів **мацератів** на основі ароматичних сполук сировини та бажаного профілю напою.

## Як це працює

1. Обираєте **цільову аудиторію** (одну): дорослі / жінки / чоловіки або спеціальні
   категорії (вагітні, діти, підлітки, спортсмени, детокс, за кермом, клуб, гурмани).
   Категорії з обмеженнями **жорстко виключають** небезпечну сировину та лишають лише
   безалкогольну основу (див. «Цільова аудиторія» нижче).
2. Обираєте **основну сировину** (текстовий ввід з підказками по перших літерах) та її
   варіант: частина (цедра / квіти / плід / корінь…), форма (свіжа / суха / екстракт /
   олія / сік) і, за потреби, з кісточкою / без кісточки.
3. Додаєте **допоміжну сировину** (до 10 рядків) у тому ж форматі.
4. Обираєте **основу**: спирт пшеничний/цукровий, вино червоне/біле, безалкогольні
   (сік, газована вода) або **ароматний дистилят з основної сировини**.
5. Обираєте **бажаний профіль** напою. Для більшості ЦА він **підставляється
   автоматично** (за категорією + обраним варіантом основної сировини) — його можна
   редагувати. Для «дорослі» — задаєте самі.
6. Натискаєте «Згенерувати» — додаток:
   - збирає ароматичні сполуки обраної сировини (залежно від частини/форми/кісточки);
   - агрегує їх у профіль (аромат, смак і **піраміду нот**: верх / серце / база);
   - порівнює з бажаним профілем (оцінка «збіг» = покриття + сила + точність);
   - для непокритих/слабких характеристик шукає чисту додаткову сировину, не
     перебиваючи профіль (anti-overpower guard);
   - балансує смак (солодке/кисле/гірке/терпке), за потреби додає підсолоджувач;
   - повертає кілька різних композицій з радаром «бажане vs досягнуте», оцінками
     збігу/балансу та поясненням, а також **оцінку досяжності** профілю.

## Стек

- Бекенд: Python + FastAPI + SQLAlchemy, база SQLite (`backend/`)
- Фронтенд: React + Vite + Tailwind (`frontend/`)
- Без авторизації/аутентифікації (за вимогами MVP)

## Запуск

### Бекенд

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

При першому старті база `backend/charkalab.db` створюється й наповнюється демо-даними.
Документація API: http://127.0.0.1:8000/docs

#### Перевірка схожості з відомими рецептами

Після генерації кожен варіант автоматично звіряється з довідником відомих
напоїв — близько 155 рецептур. Серед них **українська класика** (спотикач,
варенуха, запіканка, старка, перцівка, хріновуха, калганівка, карпатський
бальзам, наливки — вишнівка, тернівка, дулівка, кизилівка, калинівка,
обліпихова та інші), а також джини, анісові напої, амаро й трав'яні лікери,
вермути та ароматизовані вина, апельсинові/кавові/шоколадні/м'ятні та
фруктово-ягідні лікери, балтійська й скандинавська класика, локальні напої
Європи, Америки, Азії та Австралії, зокрема із захищеним географічним
зазначенням, і безалкогольна класика (тонік, узвар, масала-чай).

Показуються до **двох** найближчих рецептур — композиція цілком може
нагадувати не один напій (вишня з гвоздикою та корицею читається і як
вишнівка, і як cherry brandy). Другий збіг добирається іншого типу, щоб не
дублювати ту саму відповідь.

Впізнавання відбувається **локально** ([backend/app/services/similarity.py](backend/app/services/similarity.py))
за довідником [backend/app/known_drinks.py](backend/app/known_drinks.py) —
без зовнішніх сервісів, ключів API та мережі. Відсоток враховує, яка частка
вашого складу пояснюється цією рецептурою і наскільки повно відтворено її
характерний набір. Основа теж перевіряється: «джиновий» склад на червоному
вині джином уже не вважається.

Веб-пошук для цього не годиться: пошуковик не знає, що «ялівець + коріандр +
дягель + ірис + цитрус» — це джин, і за таким запитом віддає випадкові блоги
про настоянки.

Якщо схожість перевищує 60%, у відповіді з'являється `similarities` (назва
напою, відсоток, спільна сировина), що фронтенд показує банером
«🔎 Схожість з наявними рецептами».

Щоб додати чи змінити рецептуру, відредагуйте `KNOWN_DRINKS` у
[backend/app/known_drinks.py](backend/app/known_drinks.py) — назви сировини
мають збігатися з назвами в базі (`seed.py`).

## API

| Метод | Шлях | Опис |
|------|------|------|
| GET  | `/materials/suggest?q=` | Автодоповнення сировини; повертає синоніми та теги-протипоказання |
| GET  | `/materials/{id}/forms` | Доступні частини/форми/варіанти кісточки сировини |
| GET  | `/characteristics` | Список характеристик профілю |
| GET  | `/bases` | Список основ напою |
| GET  | `/audiences` | Список цільових аудиторій (фільтри, дефолтні профілі, дисклеймери) |
| POST | `/audiences/suggest-profile` | Популярний профіль під ЦА + обраний варіант сировини |
| POST | `/recipes/generate` | Генерація композицій під профіль (приймає `audience_id`) |

## Модель даних

- `RawMaterial` — сировина (напр. калина): `has_pit_variants` (варіанти з/без кісточки),
  `aliases` (синоніми пошуку, напр. сушені назви), `tags` (теги-протипоказання ЦА:
  `pregnancy_unsafe` / `kids_unsafe` / `caffeine`).
- `AromaCompound` — аромосполука (напр. лімонен): `kind` (`aroma`/`taste`/`both`) і
  `volatility` (`top`/`heart`/`base` — ярус ольфакторної піраміди).
- `Characteristic` — характеристика профілю (свіжий, цитрусовий…).
- `MaterialCompound` — концентрація сполуки в сировині для конкретного препарату
  (`part`, `form`, `pit`, `intensity`).
- `CompoundCharacteristic` — звʼязок сполуки з характеристикою (`weight`).
- `Base_` — основа напою (профілі, конфлікти/синергія та ABV — у `engine.BASE_PROFILES`).

## Цільова аудиторія

Сегменти описані в [backend/app/audiences.py](backend/app/audiences.py). Дві групи:

- **Дорослі** — `дорослі` (нейтральний дефолт, профіль задається вручну), `жінки`, `чоловіки`.
- **Спеціальні** — `вагітні/годуючі`, `діти`, `підлітки`, `спортсмени`, `детокс/ЗСЖ`,
  `за кермом` (усі — лише безалкогольна основа), `клуб/вечірка`, `гурмани`.

Кожен сегмент має:

- `forbidden_tags` — **жорсткий фільтр**: сировину з цими тегами виключено з підбору,
  прихована в автокомпліті, а несумісну з обраною основною сировиною ЦА **вимкнено** у виборі;
- `alcohol_free` — лишаються лише основи 0% ABV;
- `default_profile` — базові ноти, до яких додаються 1–2 природні ноти основної сировини
  (з урахуванням обраного варіанту); недосяжні на цій сировині ноти не пропонуються;
- `disclaimer` — застереження для банера.

## Наповнення бази реальними даними

Демо-дані задані структурою `SEED_DATA` у [backend/app/seed.py](backend/app/seed.py).
Та сама структура є форматом для імпорту. Щоб завантажити власні дані, можна викликати
`load_data(my_data)` з тим самим словником:

```python
{
  "characteristics": ["свіжий", "цитрусовий"],
  "bases": ["спирт пшеничний", "сік (фруктовий)"],
  "compounds": [
    {"name": "лімонен", "kind": "aroma",
     "characteristics": {"свіжий": 1.0, "цитрусовий": 1.0}}
  ],
  "materials": [
    {"name": "калина", "has_pit_variants": true, "aliases": [],
     "compounds": [
       {"compound": "лімонен", "part": "whole", "form": "fresh",
        "pit": "na", "intensity": 0.8}
     ]}
  ],
  "material_tags": {"полин": ["pregnancy_unsafe", "kids_unsafe"]}
}
```

- `part`: `whole` | `flower` | `zest` | `fruit` | `berry` | `leaf` | `root` | `bark` |
  `seed` | `herb` | `needle` | `rhizome` | `resin` | `bulb` | `stalk` | `peel`.
  Частина, яку реально беруть у настоянку: коріандр — `seed`, ірис — `rhizome`,
  кориця — `bark`. Одна сировина може мати кілька частин із **різними**
  профілями (коріандр: `seed` — тепло-цитрусовий, `herb` — зелена кінза;
  вишня: `fruit` і `leaf`). Загальний `whole` лишається тільки для того, що не
  є частиною рослини (мед, палений цукор). Відповідність задає `MATERIAL_PART`
  у [backend/app/seed.py](backend/app/seed.py).
- `form`: `fresh` | `dry` | `extract` | `oil` | `juice`
- `pit`: `with` | `without` | `na`
- `material_tags`: теги-протипоказання ЦА за назвою сировини
  (`pregnancy_unsafe` / `kids_unsafe` / `caffeine`)

Завантаження ідемпотентне за іменами (повторний імпорт не дублює записи).
